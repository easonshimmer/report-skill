# 工作报告生成 Skill

`work-report` 用于把零散工作记录整理成结构清楚、事实准确、面向读者的日报、周报、月报或年报。使用者只需提供做了什么；结果数据和接下来的方向为可选信息。

## 能做什么

- 根据周期和受众组织内容，突出重要进展、成果、风险与后续行动。
- 将活动、产出、结果和影响区分表达，避免把过程包装成未经证实的业绩。
- 保留数据的单位、范围和口径，不补造指标、日期、状态或因果关系。
- 接受零散要点、原始笔记或口述内容；也可遵循用户提供的公司模板、字数和语言要求。

## 输入内容

| 内容 | 要求 | 可以包含 |
| --- | --- | --- |
| 做了什么 | 必需 | 工作事项、项目、协作、问题处理、当前状态 |
| 结果数据 | 可选 | 数量、比例、金额、质量、时效、用户反馈、统计范围 |
| 接下来的方向 | 可选 | 下一步行动、待办、风险、依赖、需要的协调 |

同时说明报告类型（日/周/月/年）即可开始。日期范围、受众、字数、模板和语言可按需补充。不必为了使用 Skill 先把信息整理成完整报告。

## 快速开始

```text
请写一份周报，面向部门负责人，控制在 400 字以内。

做了什么：推进新版结算流程；完成支付回归测试；和客服团队梳理用户反馈。
结果数据：回归 42 条用例，通过 39 条；3 条因测试环境问题未完成。新版已进入灰度。
接下来的方向：下周跟进环境问题，完成剩余用例，并根据灰度反馈确认是否扩大范围。
```

## 不同周期的表达重点

- **日报**：今天完成了什么、当前卡点、下一步衔接。
- **周报**：本周有哪些变化和交付、重点事项状态、下周优先级。
- **月报**：阶段成果与目标进展、项目偏差、经验和下月重点。
- **年报**：全年代表性成果、持续性进展、关键经验和下一年度方向。

这些是组织建议，不是必填章节。没有相应信息时会省略，避免空洞套模板。

## 使用示例

### 只有工作事项，也可以生成

```text
帮我写日报：上午和设计确认了空状态方案，下午修复支付页的展示问题，目前等接口同学确认字段。
```

### 带有数据和后续方向

```text
整理成周报：
做了什么：完成 5 场客户访谈，推进新用户引导页改版。
结果数据：访谈记录已整理；改版页面已发布，暂时没有完整转化数据。
接下来的方向：下周复核转化数据，并按访谈发现确定一个优先优化点。
```

### 约束模板和读者

```text
请根据下面信息写一份月报，面向跨部门管理层，使用“重点进展、风险与支持、下月计划”三个栏目，控制在 300 字以内。
做了什么：……
结果数据（可选）：……
接下来的方向（可选）：……
```

## 安装与调用

将本仓库作为 Skill 使用，或把包含 `SKILL.md` 的 `work-report` 目录放入 Codex 的 skills 目录。随后可以直接提出报告需求，也可以显式调用 `$work-report`。
